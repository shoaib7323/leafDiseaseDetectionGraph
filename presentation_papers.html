Project Diagram Presentation Papers
ডায়াগ্রাম প্রেজেন্টেশন পেপারস (দ্বিভাষিক সংস্করণ)

1. CNN Architecture (MobileNetV2 based)

Objective: To illustrate the deep learning pipeline responsible for processing leaf images and extracting disease characteristics for classification.

Key Components: Input Layer, Data Pipeline (resizing/normalization), Model Core (feature extraction), and Output Layer (Softmax probability).

Presentation Note: This diagram visualizes the internal data flow by showing the transformation from raw pixels to clinical diagnosis.

১. সিএনএন আর্কিটেকচার (MobileNetV2 ভিত্তি)

উদ্দেশ্য: উদ্ভিদ পাতার রোগ শনাক্তকরণের জন্য ইমেজ প্রোসেসিং এবং বৈশিষ্ট্য সংগ্রহের জন্য ব্যবহৃত ডিপ লার্নিং পাইপলাইন চিত্রিত করা।

মূল উপাদানসমূহ: ইনপুট লেয়ার, ডাটা পাইপলাইন (রিসাইজ/নর্মালাইজেশন), মডেল কোর (বৈশিষ্ট্য সংগ্রহ), এবং আউটপুট লেয়ার।

প্রেজেন্টেশন নোট: এই ডায়াগ্রামটি কাঁচা পিক্সেল থেকে ক্লিনিকাল ডিটেকশন পর্যন্ত ডাটার স্তরবিন্যাস পরিবর্তন দেখিয়ে সিস্টেমের অভ্যন্তরীণ প্রবাহকে চিত্রিত করে।

2. UML Class Diagram

Objective: To describe the static structure of the application from an Object-Oriented Programming (OOP) perspective.

Key Components: LeafDetectorApp (Controller), CNNModel, PlantPreprocessor, and Data Entities (Treatment/KnowledgeBase).

Presentation Note: Demonstrates the modularity and scalability of the software architecture, ensuring components have single responsibilities.

২. ইউএমএল ক্লাস ডায়াগ্রাম (UML Class Diagram)

উদ্দেশ্য: একটি অবজেক্ট-ওরিয়েন্টেড প্রোগ্রামিং (OOP) দৃষ্টিকোণ থেকে অ্যাপ্লিকেশনের স্ট্যাটিক কাঠামো বর্ণনা করা।

মূল উপাদানসমূহ: LeafDetectorApp (কন্ট্রোলার), CNNModel, PlantPreprocessor এবং ডাটা এনটিটি (ট্রিটমেন্ট/নলেজ বেস)।

প্রেজেন্টেশন নোট: এটি সফটওয়্যার আর্কিটেকচারের মডুলারিটি এবং স্কেলেবিলিটি প্রদর্শন করে, যা প্রতিটি ইউনিটের নির্দিষ্ট দায়িত্ব নিশ্চিত করে।

3. UML Use Case Diagram

Objective: To map the functional requirements and determine how actors (users/admins) interact with the system.

Key Components: Primary Actor (Farmer), Secondary Actor (Model/Database), and Include/Extend relationships.

Presentation Note: Provides a stakeholder-level view of the system, identifying operational scenarios and actor boundaries.

৩. ইউএমএল ইউজ কেস ডায়াগ্রাম

উদ্দেশ্য: কার্যকারিতার প্রয়োজনীয়তা নির্ধারণ এবং বিভিন্ন অ্যাক্টর (ইউজার/অ্যাডমিন) কিভাবে সিস্টেমের সাথে যোগাযোগ করে তা ম্যাপ করা।

মূল উপাদানসমূহ: প্রাইমারি অ্যাক্টর (কৃষক/গবেষক), সেকেন্ডারি অ্যাক্টর (এমএল মডেল/ডাটাবেস) এবং ইনক্লুড/এক্সটেন্ড রিলেশন।

প্রেজেন্টেশন নোট: এই ডায়াগ্রামটি স্টেকহোল্ডার-লেভেল ভিউ প্রদান করে এবং সব ধরণের কাজের দৃশ্যপট এবং গণ্ডি চিহ্নিত করে।

4. Entity-Relationship Diagram (ERD)

Objective: To represent the relational database schema managing disease knowledge and treatment strategies.

Key Components: Treatments Table, KnowledgeBase Table, and attribute mappings (PK/Unique).

Presentation Note: The ERD highlights the system's ability to store and retrieve cross-referenced botanical data reliably.

৪. এনটিটি-রিলেশনশিপ ডায়াগ্রাম (ERD)

উদ্দেশ্য: রোগ ও প্রতিকারের কৌশল ম্যানেজমেন্টের জন্য ব্যবহার করা রিলেশনাল ডাটাবেস স্কিমা উপস্থাপন করা।

মূল উপাদানসমূহ: Treatments টেবিল, KnowledgeBase টেবিল এবং অ্যাট্রিবিউট ম্যাপিং (PK/Unique)।

প্রেজেন্টেশন নোট: এই ERD-টি ডাটবেসের বোটানিক্যাল ডাটা স্টোর এবং রিট্রিভ করার ক্ষমতা ফুটিয়ে তোলে, যা নির্ভুল ট্রিটমেন্ট নিশ্চিত করে।
